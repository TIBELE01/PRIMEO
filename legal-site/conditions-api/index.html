1. Accès à l'API et authentification

1.1 Présentation de l'API PRIMEO

L'API PRIMEO (Application Programming Interface) est une interface de programmation qui permet aux développeurs et aux entreprises partenaires d'accéder programmatiquement aux données et aux fonctionnalités de la plateforme PRIMEO, notamment les annonces immobilières, les établissements d'hébergement et de restauration, les disponibilités et les réservations. L'API est accessible via HTTPS à l'adresse api.primeo.ci.

Les présentes Conditions d'utilisation de l'API (ci-après « Conditions API ») constituent un accord juridiquement contraignant entre PRIMEO SARL et toute personne physique ou morale (ci-après « le Partenaire API ») souhaitant accéder à l'API PRIMEO. Ces Conditions API complètent les Conditions Générales d'Utilisation. En cas de contradiction, les Conditions API prévalent pour les aspects spécifiques à l'accès par API.

1.2 Conditions d'accès

L'accès à l'API PRIMEO est réservé aux entités satisfaisant les conditions suivantes :

  • Être une personne morale régulièrement immatriculée ou une personne physique majeure capable juridiquement de contracter ;
  • Avoir accepté les présentes Conditions API et les CGU de PRIMEO ;
  • Avoir soumis et obtenu l'approbation d'une demande d'accès via le portail développeur PRIMEO ;
  • Pour les partenaires commerciaux : avoir signé un accord de partenariat avec PRIMEO.

PRIMEO se réserve le droit de refuser ou de révoquer l'accès à l'API à tout Partenaire sans obligation de motivation, notamment si le projet ou l'usage envisagé est incompatible avec les valeurs ou les intérêts de PRIMEO.

1.3 Authentification par clé API

L'accès à l'API nécessite l'utilisation d'une clé API (API Key) attribuée individuellement à chaque Partenaire. Les clés API sont :

  • Générées depuis le tableau de bord du portail développeur ;
  • Strictement personnelles et non cessibles ;
  • À inclure dans l'en-tête HTTP Authorization: Bearer {API_KEY} de chaque requête ;
  • Révocables à tout moment par PRIMEO en cas de violation des Conditions API.

Le Partenaire est seul responsable de la sécurisation de sa clé API. Toute utilisation effectuée avec sa clé, qu'elle soit autorisée ou non, est réputée effectuée par le Partenaire. En cas de compromission suspectée, le Partenaire doit immédiatement régénérer sa clé depuis le portail développeur et notifier PRIMEO à api@primeo.ci.

1.4 Authentification OAuth 2.0

Pour les intégrations nécessitant d'agir au nom d'utilisateurs PRIMEO (accès aux données personnelles d'un utilisateur, réservations), l'API PRIMEO implémente le protocole OAuth 2.0. Le Partenaire doit enregistrer son application cliente dans le portail développeur pour obtenir un client_id et un client_secret. Le flux Authorization Code avec PKCE est recommandé pour les applications web et mobiles. Le flux Client Credentials est utilisé pour les accès machine à machine.

1.5 Webhooks

L'API PRIMEO propose un système de webhooks permettant de recevoir des notifications en temps réel lors d'événements spécifiques (nouvelle réservation, annulation, modification de disponibilité, etc.). Les webhooks sont configurés depuis le portail développeur. PRIMEO signe chaque notification avec une clé HMAC-SHA256 que le Partenaire doit vérifier pour s'assurer de l'authenticité des messages.

2. Limites d'utilisation et quotas

2.1 Limites de débit (Rate Limiting)

Afin de garantir la qualité de service pour l'ensemble des Partenaires, l'API PRIMEO applique des limites de débit selon le plan souscrit :

  • Plan Découverte (gratuit) : 100 requêtes par minute, 5 000 requêtes par jour ;
  • Plan Starter : 500 requêtes par minute, 50 000 requêtes par jour ;
  • Plan Business : 2 000 requêtes par minute, 500 000 requêtes par jour ;
  • Plan Enterprise : limites négociées individuellement selon les besoins.

Les limites sont contrôlées par une fenêtre glissante. Les en-têtes HTTP X-RateLimit-Limit, X-RateLimit-Remaining et X-RateLimit-Reset sont inclus dans chaque réponse pour permettre au Partenaire de gérer sa consommation. En cas de dépassement, l'API retourne une réponse HTTP 429 (Too Many Requests).

2.2 Quotas mensuels

En complément des limites de débit, des quotas mensuels s'appliquent selon le plan. En cas de dépassement du quota mensuel, les requêtes supplémentaires sont facturées à la requête (voir article 6) ou entraînent la suspension temporaire de l'accès jusqu'au renouvellement mensuel du quota.

2.3 Mise en cache et optimisation

Le Partenaire est encouragé à mettre en place une stratégie de mise en cache (caching) de son côté pour réduire le nombre de requêtes. Les réponses de l'API incluent des en-têtes Cache-Control et ETag indiquant les durées de validité recommandées. Il est interdit de désactiver ou contourner ces mécanismes pour augmenter artificiellement la fréquence des requêtes.

2.4 Limites sur les données en masse

L'extraction de données en masse (bulk) est soumise à des endpoints dédiés disponibles uniquement sur les plans Business et Enterprise. L'utilisation de l'API standard pour tenter de récupérer l'intégralité du catalogue PRIMEO par requêtes successives est interdite et peut entraîner la suspension immédiate de l'accès.

3. Données accessibles via l'API

3.1 Données publiques

Les données suivantes sont accessibles via l'API sans authentification utilisateur (avec authentification par clé API uniquement) :

  • Annonces immobilières publiques (description, localisation, prix, photos) ;
  • Informations sur les établissements d'hébergement et de restauration (nom, description, catégorie, localisation, horaires, tarifs indicatifs) ;
  • Disponibilités en temps réel des hébergements ;
  • Avis et notes publiés sur la plateforme (données agrégées) ;
  • Données géographiques (communes, quartiers, points d'intérêt).

3.2 Données nécessitant une autorisation utilisateur (OAuth)

Les données suivantes nécessitent un accès autorisé par l'utilisateur concerné via OAuth 2.0 :

  • Profil utilisateur (nom, email, préférences) ;
  • Historique de réservations de l'utilisateur ;
  • Favoris et listes personnalisées ;
  • Messages de la messagerie interne ;
  • Actions au nom de l'utilisateur (création de réservation, annulation, publication d'avis).

3.3 Données réservées aux partenaires certifiés

Certaines données sont accessibles uniquement aux partenaires ayant signé un accord de partenariat spécifique avec PRIMEO :

  • Données analytiques agrégées du secteur (tendances des prix, taux d'occupation) ;
  • Export de catalogue complet pour les agences immobilières partenaires ;
  • Données de performance des annonces pour les professionnels hébergeurs.

3.4 Propriété des données

Les données accessibles via l'API PRIMEO restent la propriété de PRIMEO et/ou des membres qui les ont publiées. L'accès à ces données via l'API ne confère au Partenaire aucun droit de propriété sur lesdites données. Le Partenaire ne peut utiliser les données que dans le cadre des usages autorisés par les présentes Conditions API.

4. Interdictions et usages prohibés

4.1 Interdictions générales

Il est strictement interdit d'utiliser l'API PRIMEO pour :

  • Reproduire, redistribuer ou revendre les données PRIMEO à des tiers sans accord préalable écrit ;
  • Créer une application ou un service concurrent directement à PRIMEO utilisant les données de la plateforme ;
  • Contourner les mécanismes d'authentification ou de contrôle d'accès ;
  • Tester la résistance des systèmes PRIMEO (tests de charge, fuzzing, scanning de vulnérabilités) sans autorisation écrite préalable ;
  • Utiliser les données personnelles des utilisateurs PRIMEO à des fins non déclarées ou incompatibles avec les finalités autorisées ;
  • Entraîner des modèles d'intelligence artificielle avec les données PRIMEO sans accord spécifique.

4.2 Attribution obligatoire

Toute application ou service utilisant des données PRIMEO accessibles via l'API doit afficher de manière visible et lisible la mention « Données fournies par PRIMEO » (ou « Powered by PRIMEO ») accompagnée d'un lien vers primeo.ci. Le Partenaire ne peut pas utiliser cette attribution pour suggérer que PRIMEO cautionne ou approuve le service du Partenaire sans accord écrit explicite.

4.3 Restrictions relatives aux données personnelles

L'utilisation des données personnelles accessibles via l'API est strictement encadrée par la loi ivoirienne n°2013-450. Le Partenaire qui accède à des données personnelles via OAuth agit en qualité de sous-traitant de PRIMEO et doit :

  • Traiter les données uniquement pour les finalités autorisées par l'utilisateur ;
  • Ne pas croiser les données PRIMEO avec d'autres bases de données sans autorisation explicite ;
  • Supprimer les données dès que l'accès OAuth est révoqué par l'utilisateur ;
  • Mettre en place des mesures de sécurité adéquates pour protéger les données.

5. Responsabilité et garanties

5.1 Disponibilité de l'API

PRIMEO s'efforce de maintenir l'API disponible 24h/24 et 7j/7, avec un objectif de disponibilité de 99,5 % sur une base mensuelle pour les plans Business et Enterprise (SLA). Aucune garantie de disponibilité n'est offerte pour le plan Découverte. Les maintenances planifiées sont annoncées avec un préavis minimum de quarante-huit (48) heures via le portail développeur et le tableau de bord du Partenaire.

5.2 Exactitude des données

Les données disponibles via l'API PRIMEO sont fournies « en l'état » (as-is). PRIMEO s'efforce de maintenir leur exactitude mais ne garantit pas que les informations sont à jour, exactes ou complètes à tout moment. Le Partenaire utilise ces données sous sa propre responsabilité et doit mettre en place les vérifications nécessaires avant de les présenter à ses propres utilisateurs.

5.3 Limitation de responsabilité

Dans les limites autorisées par le droit ivoirien et le droit OHADA, PRIMEO n'est pas responsable des dommages indirects, consécutifs, spéciaux ou punitifs subis par le Partenaire du fait de l'utilisation ou de l'impossibilité d'utiliser l'API. La responsabilité totale de PRIMEO envers un Partenaire ne saurait excéder les sommes effectivement versées par ce Partenaire à PRIMEO au cours des trois (3) mois précédant l'événement dommageable.

5.4 Responsabilité du Partenaire

Le Partenaire est entièrement responsable des applications et services qu'il développe en utilisant l'API PRIMEO, notamment :

  • De la conformité de son application avec la législation ivoirienne et les législations applicables à ses utilisateurs ;
  • De la sécurité de son application et de la protection des données personnelles qu'il traite ;
  • Du respect des droits de propriété intellectuelle de PRIMEO et de tiers ;
  • De l'exactitude des informations présentées à ses utilisateurs sur la base des données PRIMEO.

6. Facturation et plans API

6.1 Plan Découverte (gratuit)

Le Plan Découverte est gratuit et permet aux développeurs de tester l'API PRIMEO pour des projets personnels, des prototypes ou des petites applications. Il est limité à 5 000 requêtes par jour et ne donne pas accès aux données en masse ni aux SLA de disponibilité. Il est interdit d'utiliser le Plan Découverte pour une application commerciale dépassant les seuils de quota.

6.2 Plans payants

Les plans payants (Starter, Business, Enterprise) sont facturés mensuellement ou annuellement (avec réduction pour le paiement annuel) en francs CFA (XOF). Les tarifs en vigueur sont disponibles sur le portail développeur. PRIMEO se réserve le droit de modifier ses tarifs avec un préavis de soixante (60) jours. Le Partenaire bénéficiant d'un plan annuel est protégé contre toute hausse de tarif jusqu'au renouvellement de son contrat annuel.

6.3 Facturation à l'usage

En cas de dépassement des quotas inclus dans le plan, les requêtes supplémentaires sont facturées selon le barème en vigueur sur le portail développeur. Le Partenaire peut configurer des alertes de consommation et des plafonds de dépenses depuis son tableau de bord pour éviter les dépassements non anticipés.

6.4 Modalités de paiement

Le paiement s'effectue par virement bancaire, mobile money (Orange Money, MTN Money) ou carte bancaire via le système de paiement sécurisé PRIMEO. Les factures sont émises en début de mois pour la consommation du mois précédent. En cas de défaut de paiement, PRIMEO peut suspendre l'accès à l'API après un rappel resté sans effet pendant quinze (15) jours.

7. Modifications et résiliation

7.1 Versionnage de l'API

L'API PRIMEO suit un schéma de versionnage sémantique (v1, v2, etc.). Chaque version majeure est maintenue pendant une période minimale de dix-huit (18) mois après la publication de la version suivante (période de dépréciation). Pendant cette période, le Partenaire est notifié et encouragé à migrer vers la nouvelle version. À l'issue de la période de dépréciation, la version ancienne peut être désactivée.

7.2 Modifications des Conditions API

PRIMEO peut modifier les présentes Conditions API avec un préavis de trente (30) jours. La poursuite de l'utilisation de l'API après l'entrée en vigueur des nouvelles Conditions vaut acceptation. Pour les modifications substantielles affectant les droits des Partenaires, un délai de préavis de soixante (60) jours est accordé.

7.3 Résiliation par le Partenaire

Le Partenaire peut résilier son accès à l'API à tout moment en supprimant ses clés API depuis le portail développeur et en notifiant PRIMEO à api@primeo.ci. En cas d'abonnement annuel prépayé, aucun remboursement au prorata n'est accordé sauf accord exprès de PRIMEO.

7.4 Résiliation par PRIMEO

PRIMEO peut résilier l'accès d'un Partenaire à l'API pour violation des présentes Conditions, avec effet immédiat en cas de violation grave (fraude, utilisation illicite des données) ou avec un préavis de trente (30) jours pour d'autres motifs. En cas de résiliation pour faute imputable à PRIMEO, les sommes prépayées non utilisées sont remboursées au prorata.

7.5 Effets de la résiliation

À la résiliation, le Partenaire doit : cesser immédiatement d'utiliser l'API ; supprimer toutes les données PRIMEO stockées en cache ou en base de données (sauf obligations légales de conservation) ; cesser d'afficher les données PRIMEO dans ses applications. Les dispositions relatives à la propriété intellectuelle, à la confidentialité et à la limitation de responsabilité survivent à la résiliation.

Support développeur : Pour toute question technique relative à l'API ou pour soumettre une demande d'accès, contactez l'équipe API à api@primeo.ci ou consultez la documentation disponible sur le portail développeur.
